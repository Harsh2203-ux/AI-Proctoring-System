AI Proctoring System — Migration Report

FastAPI + MongoDB + WebSocket → Vercel Serverless + PostgreSQL + HTTP Polling  |  Build: ✓ PASSING

Architecture Change

Before
  • FastAPI (Python) — port 8000
  • AI service (FastAPI) — port 8001
  • MongoDB via Motor async driver
  • WebSocket /ws/proctoring/:id
  • Local file storage for evidence
  • Docker Compose for orchestration
After
  • Vercel Serverless Functions (Node.js/TS)
  • Demo AI logic inline in serverless fn
  • PostgreSQL (Neon / Vercel Postgres)
  • HTTP polling — POST /api/proctoring/events
  • Evidence stored as base64 in DB
  • Single vercel.json — no Docker

Deployment Steps

  1. Create a Neon database at neon.tech (free tier works). Copy the connection string.
  2. Run migrations locally:
    DATABASE_URL=postgres://... node -r ts-node/register api/db/migrate.ts
  3. Seed demo data:
    DATABASE_URL=postgres://... node -r ts-node/register api/db/seed.ts
  4. Push to GitHub and import the repo into Vercel.
  5. Set environment variables in Vercel Project → Settings → Environment Variables (all 8 from the table above).
  6. Deploy — Vercel auto-detects vercel.json, builds frontend/, and serves api/ as serverless functions.
  7. Verify: visit https://your-app.vercel.app/api/health — should return {"status":"ok","db":"connected"}
  8. Log in with demo credentials: admin@demo.com / Admin@1234 or student@demo.com / Student@1234

Limitations & Known Constraints

  • DEMO ONLY Real face-recognition AI (face_recognition / dlib) cannot run on Vercel serverless (no binary deps, 50 MB limit). DEMO_MODE is the only supported mode for Vercel deployment. To use real AI, you would need a separate persistent service (e.g., a Railway/Render Python container) and call it from the serverless function via HTTP.
  • EVIDENCE SIZE Evidence files are stored as base64 in PostgreSQL. This is suitable for demo but not for high-volume production use. For production, move to Vercel Blob or S3.
  • PDF REPORTS The legacy PDF generation (reportlab) is not available serverless. The GET /api/admin/reports/:id/pdf route from the original backend is not implemented in the new API. Report data is available as JSON only.
  • PROCTORING LATENCY HTTP polling at 1 fps for frames and 3s heartbeats introduces slightly more latency than WebSocket. This is an acceptable trade-off for serverless deployment.
  • VIOLATION STATE Per-session proctoring state (consecutive frame counters) is persisted in the vstate JSONB column, making it safe for stateless serverless invocations.
